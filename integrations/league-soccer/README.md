# League-Soccer native integration — pilot 1

The selected upstream is [League-Soccer](https://github.com/awest813/League-Soccer), pinned in upstream.json. This pilot compiles the actual native C++ match and records the ball and active players from Match::Process, not a synthetic score generator or the MatchClock test. The Apache-2.0 source license remains in the checkout; the added trace hook is marked as a modification. Do not redistribute upstream assets before a separate rights audit.

## Run (Linux)
Install the upstream Linux build dependencies, or set TRIBUN_INSTALL_NATIVE_DEPS=1 to let its documented installer do so. From the Tribun repo:
```sh
TRIBUN_INSTALL_NATIVE_DEPS=1 bash integrations/league-soccer/run-pilot.sh /tmp/tribun-league-soccer.ndjson
```
Open integrations/league-soccer/replay.html in a browser and choose the generated trace. The CI workflow also uploads the recording. Native coordinates are x/y on the pitch and z vertical; the Tribun renderer uses x/z horizontally and y vertically. Do not guess yaw or attack direction until verified against real footage.

The upstream full-match smoke config uses a 5-minute active-play setting and a 6x accelerated test clock; this validates a native full-time run, **not** the required 300-second wall-clock broadcast. Upstream runs with SDL/OpenGL under Xvfb; its headless test target only exercises independent modules, not the full Match.

## Production gate
The existing live-match-worker.cjs and live_match.py remain unchanged and authoritative. No existing fixture changes engine mid-match. Before switching: accept frozen roster IDs, player attributes, tactics and deterministic seed from server; run two CPU-controlled teams without menu smoke automation; expose init/advance/kick JSONL with native 10 ms steps and explicit 60 Hz conversion; supply events, cards, substitutions, appearances and complete snapshot contract; verify deterministic crash recovery and correct season persistence; map native positions into existing 3D renderer; enforce 300-second wall time separately from game clock; measure shot volume, box entries, goals, keeper actions, CPU and concurrency versus current engine. Do not silently fall back within a fixture or enable the native backend before these checks pass.

## Pilot 2: frozen fixture input
Pass an exported server live_config JSON as the second argument, or use the explicit fictional `--demo` fixture. The adapter requires both starting elevens and supports all six Tribun formations. It preserves roster-to-native ID mapping, reuses PlayerModel.forSlot effective attributes, and maps pressure, counter-attack and support distance to actual upstream tactic keys. Other controls are not claimed to work. Wingers use CF with wide coordinates; wingbacks use LB/RB. Native attribute mappings are approximations (e.g. crossing -> high pass); the source has no independent preferred-foot or goalkeeper-specific attribute in this import. The seed is recorded but not yet applied to native random state. The native patch replaces TeamData players/formation before Match initialization; it does not use upstream database ratings. Only starters are imported in this pilot; bench, substitutions, club visual identity and live fixture activation remain out of scope. CI runs the adapter tests and verifies the native trace contains both imported elevens.

## Pilot 3: native trace in the existing Tribun 3D stadium
Serve the repo locally (e.g. `node tools/serve-character-viewer.cjs`) and open `http://127.0.0.1:8088/integrations/league-soccer/replay.html`. Import the native NDJSON and optional matching .fixture.json artifact. The renderer reuses Stadium3D, licensed player assets, existing procedural animation rig, camera and graphics quality modes. Coordinates map native (x,y,z) to Tribun (x,z,-y) in x/y/z order; the native world heading is mapped with atan2(-y,x). Interpolation changes presentation only; score and stats come from native frames, not old AI. Gaps and missing actors are not invented. Goalkeeper and six statistical categories are exported directly. Locomotion is inferred from velocity; no native kick/duel animation metadata is claimed. The browser test uses clearly synthetic render contract samples, not football performance evidence. Run it against an actual artifact as `node integrations/league-soccer/replay-browser.cjs /path/to/trace.ndjson`. Verify orientation against a real native recording. This is a replay pilot, not an authoritative online fixture or a fixed 300-second broadcast.

## Pilot 4: fixed-duration broadcast and native attack report
A completed native recording can be replayed in exactly 300 seconds using the separate broadcast button. The wall clock is monotonic and independent of render FPS; if the browser is hidden it catches up when visible. Playback is rescaled, not new native simulation. For a shared read-only proof of concept:
```sh
node integrations/league-soccer/broadcast-server.cjs /tmp/tribun-league-soccer.ndjson
```
The loopback API starts ten seconds later (or accepts an explicit ISO kickoff), computes its phase from server time without viewers, returns only the due frame and cannot mutate the fixture. No production league integration or remote deployment is implied. The current browser broadcast button uses local file playback, not the pilot API.

Native trace now includes open-play flag, attack direction and player unique possession. `attack-report.cjs` emits .attack.json alongside the recording. Cumulative shots, on-target, passes, completed passes, fouls and possession are direct native stats. Sampled controlled final-third/box time, box crossings and goalkeeper-control time are observational metrics using the native 110x72 pitch, not exact dribbles/saves or an xG model. Gaps above 250 ms and dead-ball/side-switch intervals are excluded. No goals are invented or added. The accelerated smoke may not produce representative attack volume; use unaccelerated multi-seed native matches before tuning or claiming superiority.

## Pilot 5: paired short-match attack experiments
The opt-in native patch seeds C rand, the MT19937 stream and fast RNG from the frozen fixture seed. This is initial RNG control, not proof of deterministic scheduling or recovery. The experimental `short-match` profile makes eligible attacking runs earlier and slightly longer, biases progressive pass selection and lowers the shot-odds threshold from 0.55 to 0.50. It preserves the underlying native angle/odds tests, pass logic, physics and rules. Baseline behavior remains default; no automatic promotion.
Run `TRIBUN_BENCHMARK=1 TRIBUN_BENCHMARK_SEEDS="2026 2027 2028" bash integrations/league-soccer/run-pilot.sh /tmp/attack-benchmark --demo`. One build, separate fresh processes, same frozen lineup and paired initial seeds; match time scale 1 instead of 6. The upstream menu automation still launches and finishes matches; active play is five minutes, total wall time may be longer. The comparison JSON reports measured differences only. CI automatically runs one pair on the initial patch; workflow_dispatch supports up to six seeds. A larger sample, verified actual timings, and renderer/live worker integration remain production gates.

## Pilot 6: Python league shadow integration
Prepare once on Linux (outside the served repository):
```sh
TRIBUN_INSTALL_NATIVE_DEPS=1 TRIBUN_PREPARE_ONLY=1 TRIBUN_NATIVE_RUNTIME_OUT=/tmp/tribun-runtime bash integrations/league-soccer/run-pilot.sh /tmp/unused.ndjson
TRIBUN_NATIVE_SHADOW=1 TRIBUN_NATIVE_RUNTIME=/tmp/tribun-runtime python3 server.py
```
At kickoff, the existing transaction freezes the exact fixture and enqueues an optional shadow job. A separate single worker claims jobs, copies a prepared runtime into an isolated temporary directory, runs the native CPU match using the frozen config, validates player IDs and the final trace, and stores compressed recordings and reports in SQLite. It never changes the authoritative JS result, player fitness or league table. No browser request runs native code. One dev server per database; restart recovers an interrupted claim once. The authenticated GET /api/league/native-pilot?round=0 exposes job state and report only after the 300-second kickoff window. Baseline is default; opt-in TRIBUN_NATIVE_SHADOW_PROFILE=short-match for experiments. Production activation requires reliable runtime performance, real live streaming, cards/appearances and manager commands. The menu smoke-based execution uses accelerated native clock, not a 300-second real-time simulation; it is not a production engine switch.

## Pilot 7: shared league shadow broadcast
Open native-match.html?round=0 with a valid league session. The league center links to the pilot separately from the official match. The authenticated GET /api/league/native-pilot/broadcast?round=0 reads an indexed due frame from SQLite; the complete recording is never sent. The shared 300-second clock begins at max(kickoff, native-record-ready time), so queued jobs may delay the pilot relative to the official fixture. Both clients see the same due frame at the same server timestamp; late join works without local simulation. The report is withheld until this separate pilot broadcast finishes. Newly completed traces are indexed atomically with the archive; old pre-index pilot records are explicitly unindexed and require regeneration. The existing Stadium3D and rig are reused; native 110x72 pitch is scaled to the 104x68 renderer. Browser interpolates only already received samples, not future frames. Shadow results are not authoritative; no substitutions, interactive manager kicks or true in-progress native streaming yet.

## Pilot 8: native player participation and season candidate
The C++ trace now records all players (including dismissed players), native card code, nominal regulation milliseconds, actual active-play milliseconds, sprint milliseconds (>=6 m/s), and native fatigue factor. The counters are accumulated at Match::Process cadence, exclude extra/stoppage minutes from nominal season minutes, and skip phase resets or abnormal clock gaps. The fixture adapter preserves roster UID and frozen starting fitness. The Python candidate converter rejects missing or duplicate players, unsupported card codes, incomplete results and invalid durations; it uses the existing season appearance contract. A disposable in-memory database exercises the current season writer to produce a fitness preview, not a real historical suspension projection. The official league database is never mutated by the shadow engine. Native fatigue factor is recorded separately from Tribun's existing fitness formula. The season candidate is included in the shadow report after broadcast completion. Bench substitutions, abandoned games, zero-minute discipline and full authoritative settlement remain explicit blockers; those cases are not silently fabricated.

## Pilot 9: bench and preplanned halftime substitutions
The frozen fixture may include up to seven eligible reserves per side and `nativeSubstitutions: [[{out: rosterId, in: rosterId}], []]` (max five unique changes per team). The C++ patch activates the new player in the outgoing player's formation slot at the second-half transition; CPU only, dead ball only, no replacement of a dismissed player and no re-entry. A fresh reserve gets its own native identity and attributes. The trace retains all starter and bench participation and the candidate records performed versus skipped changes. This is explicitly not live manager control, an automatic substitution policy, or an official result. CI runs a two-sided planned native substitution demo and checks the final report. Browser identity mapping includes the bench; unused players are ignored by the existing season writer. Runtime rebuild is required.

## Pilot 10: live native manager tactics mailbox
A trusted local operator can change four actual native tactics during a running CPU match. Create a fresh private directory per match and pass `TRIBUN_LEAGUE_SOCCER_COMMAND_DIR=/path/to/private-mailbox` to run-frozen.sh. From another terminal:
```sh
python3 integrations/league-soccer/manager-control.py /path/to/private-mailbox 0 1 0 85 70 60 75
```
Arguments are team (0/1), increasing revision, earliest regulation match milliseconds, pressure, counterattack, support distance and width (0–100). The latest pending command per team wins; writing does not mean applied. The native loop polls at 200 ms engine-time intervals in regulation open play, applies real TeamData properties and refreshes the team AI, and emits the acknowledged revision, application timestamps and values in each subsequent frame. Revision 0 means no command has been applied; its neutral values are placeholders, not current tactics. Invalid, stale or future commands are ignored until eligible; no commands apply at full-time. The CI test submits both sides' commands only after real native output begins and sends a second revision after acknowledgement. This is a local process-control experiment, not an authenticated online manager endpoint. Frozen official/shadow matches do not inherit the mailbox. Live browser control, command persistence/recovery, substitutions at arbitrary stoppages, formations and tempo still require work.

## Pilot 11: dynamic formation and decision tempo
The local mailbox now supports `--tempo 85 --formation 442`; supported preset codes are 433, 442, 4231, and 0 (keep shape). V1 command files remain readable; V2 contains tempo and formation. The C++ engine uses minimum-cost assignment of the ten active outfield players to new tactical formation entries, favoring existing roles and proximity in formation space. It keeps the goalkeeper, changes actual TeamData and dynamic-role targets, and never teleports a player. Preset switching requires eleven eligible players; a command requesting a shape after dismissal is not acknowledged (send formation 0 for tactics only). Tempo adjusts the existing pass-decision rating threshold by at most ±0.03; neutral 50 preserves prior behavior and passing-odds constraints stay unchanged. This is an experimental decision bias, not a physical speed multiplier or proven attack improvement. The trace contains actual formation roles and targets plus applied tempo and formation. The smoke test requests 4-4-2 and then 4-2-3-1 and asserts the real native targets. No authenticated online write endpoint or official result switch yet.

## Pilot 12: observable-match manager advisor
The read-only shadow viewer now includes a side-selectable advisor. It uses only received frames, not final reports or future data. Score/remaining regulation time drive chase/protect/short-handed suggestions, and a rolling 8–15 minute observed stats window detects shot drought or opponent pressure. Late join must accumulate observations; stale packets and counter resets cannot synthesize a trend. Formation targets yield a coarse opponent line distribution, not a guaranteed tactical counter. Relative native fatigue (not fitness percent), minutes, same positional group, starting fitness, rating and unused bench status determine up to two replacement suggestions. Five-change budget and dismissals are respected conservatively. Advice is not applied, does not rewrite completed recordings, and does not affect official league results. Thresholds are experimental; no claimed performance uplift until benchmark validation. The unit tests cover score states, missing telemetry, stale data, dismissals, and bench eligibility.

## Pilot 13: interactive native league shadow session
Set both TRIBUN_NATIVE_SHADOW=1 and TRIBUN_NATIVE_INTERACTIVE=1 before kickoff to opt newly queued fixtures into interactive native mode. The isolated process uses upstream smoke time scale 1, not 6. A worker tails complete NDJSON records while the process runs; the authenticated existing broadcast route returns the newest observed frame and control availability. A new POST /api/league/native-pilot/tactics derives the team from the existing league token and fixture, not request body. It validates all six values, server-assigns revisions, limits commands to one per two seconds per team and 120 per match, and handles repeated request IDs in memory. Commands are written atomically to private per-match mailboxes. Only engine acknowledgement counts as applied. The final frame is withheld until the archive and season candidate pass validation; interrupted interactive sessions fail closed, rather than restarting with lost commands. Existing frozen replay mode remains unchanged. The browser has a separate control panel for this mode. Single dev server, one native worker; other fixtures may queue. Real process duration includes startup and stoppages and is NOT guaranteed to be exactly 300 wall seconds. No official standings writes, live recovery, concurrent fixture capacity proof or public deployment. Enable only in a test league.

CI run 45713855969 reported the C++ error from chained Vector3 assignment (its operator= returns void); the formation assignment is now split. Run 45713339747 compiled but crashed during reserve activation immediately after setting the kit. That crash is not proven fixed. Real-time 300 seconds remains a release gate: native football clock advances only during open play, and setup, restarts, halftime and added time mean scale=1 does not guarantee 300 wall seconds. No truncation or fake full-time result. Existing official engine remains authoritative.

## Pilot 15: experimental reserve lifecycle repair
The previous native test crashed during mid-match reserve model creation. This patch changes the planned reserve lifecycle: during initial team construction, only planned incoming players receive a model, controller and captions; they are immediately parked (inactive, hidden). At halftime the original eleven-slot formation mapping is transferred to the incoming player, the outgoing player is deactivated, and the existing reserve is resumed without allocating new graphics objects. A temporary formation lookup entry prevents indexing the eleven-slot array with a reserve index. An unsuccessful resume fails the diagnostic instead of publishing a partial result. Diagnostic logs mark preparation, parking and substitution. The exact original crash cause is not established and this alternative still needs real native verification. Ordinary runs still reject planned substitutions; the opt-in diagnostic stays available. No official league activation.

The separate reserve lifecycle diagnostic workflow automatically runs on reserve-patch changes and checks actual frame identities before and after halftime, not merely a final report flag. It does not remove the quarantine.

## Pilot 16: measured five-minute duration calibration
Normal behavior is unchanged. The standalone diagnostic runs three frozen fixtures with identical initial seed: baseline scale 1.0, opt-in quicker ordinary ball-out restarts at 1.0, and quicker restarts at 1.25. The referee only shortens throw-in, corner and goal-kick preparation when there is no foul or period transition; it never moves a 10ms deadline into the past. The timing benchmark partitions native elapsed intervals into open play, dead ball, set piece, transitions and sampling gaps, and independently measures monotonic observed first open play to validated full time. It reports the actual difference from 300 seconds, alongside shots and controlled box entries. One fixture per profile is calibration only; no claimed improvement or exact-duration guarantee. Both diagnostic environment variables are scrubbed from regular league shadow jobs. The separate CI workflow builds once then validates every match. No official engine switch.

## Pilot 17: CPU-only fixtures and progressive attack policy
Previous successful full-match CI (45714831533) completed an accelerated smoke with one shot and zero controlled penalty-area entries; this is not a normal-speed benchmark. Native manager fixtures now suppress human controller assignment at Match::UpdateControllerSetup, and every recorded frame must prove zero human gamers on both sides. The experimental short-match profile blends goalward dribbling only for uniquely controlling outfield players in open play with an unobstructed corridor and enough room before the byline; existing velocity, animation and collision constraints remain in force. An already accepted shot with good angle, distance and odds is placed before normal pass alternatives, but still must pass native animation selection. No forced goals or fabricated actions. Tests compile the real patched C++ policy predicates before the full build. Attack reports additionally track sampled same-carrier forward/backward ball displacement and time, excluding jumps; these are proxies, not dribble counts. Existing baseline remains unchanged except CPU-only enforcement in imported manager fixtures. No claimed improvement until matched normal-speed results are available.

## Pilot 18: collective attack and running-pass selection
The experimental short-match profile selects an eligible onside midfield/forward runner based on longitudinal progress, passable distance, role and lateral separation, then selects a separate short support outlet rather than assigning both jobs to the same player. The native controller's existing long/lead pass is considered when an onside teammate is moving forward and the native interception estimate is at least 0.65; normal pass safety, rating thresholds and animation selection remain. These are heuristic preferences, not guaranteed through balls, scripted goals, or a dedicated give-and-go system. The baseline profile preserves existing decisions. New sampled metrics describe time under control with a forward teammate within 32 m, and time with at least two teammates in the attacking box; they are spatial proxies, not verified pass lanes or completed runs. Paired reports now include these alongside progressive/regressive same-carrier metres. Real match validation is still required. C++ predicate and synthetic telemetry tests are included.

## Pilot 19: wide attack, cutback and distance-shot decisions
Only in the experimental short-match profile, controlled wide possession creates two bounded box support targets for the already assigned runner and distinct support outlet. Existing formation attraction, offside clamp, collision and animation logic still govern movement. The pass selector evaluates a central box receiver, favoring safe native short passes for cutbacks and native high passes when suitable; it requires an onside margin and interception score and keeps normal rating competition. Native high-pass odds include a 0.4 penalty and are capped at 0.6; a separate 0.54 aerial floor allows at most 0.06 additional danger. This is a heuristic threshold, not a calibrated probability. Distance shots extend the existing search only for well-aligned skilled players 17–26 m from goal, with strong native shot odds. Reports measure wide controlled possession and central box outlet availability, not executed cross counts. Dedicated give-and-go state, overlaps and rebound decisions remain future work. No changes to visual assets or official engine.
