# League-Soccer native integration — pilot 1

The selected upstream is [League-Soccer](https://github.com/awest813/League-Soccer), pinned in upstream.json. This pilot compiles the actual native C++ match and records the ball and active players from Match::Process, not a synthetic score generator or the MatchClock test. The Apache-2.0 source license remains in the checkout; the added trace hook is marked as a modification. Do not redistribute upstream assets before a separate rights audit.

## Run (Linux)
Install the upstream Linux build dependencies, or set TRIBUN_INSTALL_NATIVE_DEPS=1 to let its documented installer do so. From the Tribun repo:
```sh
TRIBUN_INSTALL_NATIVE_DEPS=1 bash integrations/league-soccer/run-pilot.sh /tmp/tribun-league-soccer.ndjson
```
Open integrations/league-soccer/replay.html in a browser and choose the generated trace. The CI workflow also uploads the recording. Native coordinates are x/y on the pitch and z vertical; the Tribun renderer uses x/z horizontally and y vertically. Do not guess yaw or attack direction until verified against real footage.

The upstream full-match smoke config uses a 5-minute active-play setting and a 6x accelerated test clock; this validates a native full-time run, **not** the required 300-second wall-clock broadcast. Upstream runs with SDL/OpenGL under Xvfb; its headless test target only exercises independent modules, not the full Match.

## Production gate
The existing live-match-worker.cjs and live_match.py remain unchanged and authoritative. No existing fixture changes engine mid-match. Before switching: accept frozen roster IDs, player attributes, tactics and deterministic seed from server; run two CPU-controlled teams without menu smoke automation; expose init/advance/kick JSONL with native 10 ms steps and explicit 60 Hz conversion; supply events, cards, substitutions, appearances and complete snapshot contract; verify deterministic crash recovery and correct season persistence; map native positions into existing 3D renderer; enforce 300-second wall time separately from game clock; measure shot volume, box entries, goals, keeper actions, CPU and concurrency versus current engine. Do not silently fall back within a fixture or enable the native backend before these checks pass.

## Pilot 2: frozen fixture input
Pass an exported server live_config JSON as the second argument, or use the explicit fictional `--demo` fixture. The adapter requires both starting elevens and supports all six Tribun formations. It preserves roster-to-native ID mapping, reuses PlayerModel.forSlot effective attributes, and maps pressure, counter-attack and support distance to actual upstream tactic keys. Other controls are not claimed to work. Wingers use CF with wide coordinates; wingbacks use LB/RB. Native attribute mappings are approximations (e.g. crossing -> high pass); the source has no independent preferred-foot or goalkeeper-specific attribute in this import. The seed is recorded but not yet applied to native random state. The native patch replaces TeamData players/formation before Match initialization; it does not use upstream database ratings. Only starters are imported in this pilot; bench, substitutions, club visual identity and live fixture activation remain out of scope. CI runs the adapter tests and verifies the native trace contains both imported elevens.

## Pilot 3: native trace in the existing Tribun 3D stadium
Serve the repo locally (e.g. `node tools/serve-character-viewer.cjs`) and open `http://127.0.0.1:8088/integrations/league-soccer/replay.html`. Import the native NDJSON and optional matching .fixture.json artifact. The renderer reuses Stadium3D, licensed player assets, existing procedural animation rig, camera and graphics quality modes. Coordinates map native (x,y,z) to Tribun (x,z,-y) in x/y/z order; the native world heading is mapped with atan2(-y,x). Interpolation changes presentation only; score and stats come from native frames, not old AI. Gaps and missing actors are not invented. Goalkeeper and six statistical categories are exported directly. Locomotion is inferred from velocity; no native kick/duel animation metadata is claimed. The browser test uses clearly synthetic render contract samples, not football performance evidence. Run it against an actual artifact as `node integrations/league-soccer/replay-browser.cjs /path/to/trace.ndjson`. Verify orientation against a real native recording. This is a replay pilot, not an authoritative online fixture or a fixed 300-second broadcast.

## Pilot 4: fixed-duration broadcast and native attack report
A completed native recording can be replayed in exactly 300 seconds using the separate broadcast button. The wall clock is monotonic and independent of render FPS; if the browser is hidden it catches up when visible. Playback is rescaled, not new native simulation. For a shared read-only proof of concept:
```sh
node integrations/league-soccer/broadcast-server.cjs /tmp/tribun-league-soccer.ndjson
```
The loopback API starts ten seconds later (or accepts an explicit ISO kickoff), computes its phase from server time without viewers, returns only the due frame and cannot mutate the fixture. No production league integration or remote deployment is implied. The current browser broadcast button uses local file playback, not the pilot API.

Native trace now includes open-play flag, attack direction and player unique possession. `attack-report.cjs` emits .attack.json alongside the recording. Cumulative shots, on-target, passes, completed passes, fouls and possession are direct native stats. Sampled controlled final-third/box time, box crossings and goalkeeper-control time are observational metrics using the native 110x72 pitch, not exact dribbles/saves or an xG model. Gaps above 250 ms and dead-ball/side-switch intervals are excluded. No goals are invented or added. The accelerated smoke may not produce representative attack volume; use unaccelerated multi-seed native matches before tuning or claiming superiority.

## Pilot 5: paired short-match attack experiments
The opt-in native patch seeds C rand, the MT19937 stream and fast RNG from the frozen fixture seed. This is initial RNG control, not proof of deterministic scheduling or recovery. The experimental `short-match` profile makes eligible attacking runs earlier and slightly longer, biases progressive pass selection and lowers the shot-odds threshold from 0.55 to 0.50. It preserves the underlying native angle/odds tests, pass logic, physics and rules. Baseline behavior remains default; no automatic promotion.
Run `TRIBUN_BENCHMARK=1 TRIBUN_BENCHMARK_SEEDS="2026 2027 2028" bash integrations/league-soccer/run-pilot.sh /tmp/attack-benchmark --demo`. One build, separate fresh processes, same frozen lineup and paired initial seeds; match time scale 1 instead of 6. The upstream menu automation still launches and finishes matches; active play is five minutes, total wall time may be longer. The comparison JSON reports measured differences only. CI automatically runs one pair on the initial patch; workflow_dispatch supports up to six seeds. A larger sample, verified actual timings, and renderer/live worker integration remain production gates.
